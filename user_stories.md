# Пользовательские истории Smart Clinic Management System

Документ описывает требования к системе управления клиникой. Истории являются планом функциональности, а не утверждением о её текущей реализации. Панели администратора и врача создаются на React и взаимодействуют с REST API Spring Boot.

## Администратор

### ADM-01 — Вход в панель управления
Как администратор, я хочу входить в систему с помощью своих учётных данных, чтобы управлять клиникой через защищённую панель.

Критерии приёмки:
- При корректных данных открывается панель администратора.
- При неверных данных отображается сообщение об ошибке без предоставления доступа.
- Сервер отклоняет административные операции пользователей без соответствующей роли.

### ADM-02 — Управление врачами
Как администратор, я хочу добавлять врачей и редактировать их профиль, специализацию и контактные данные, чтобы поддерживать актуальный состав клиники.

Критерии приёмки:
- Обязательные поля проверяются перед сохранением.
- Повторное создание учётной записи с тем же уникальным идентификатором входа отклоняется.
- Сохранённые изменения отображаются в списке врачей.

### ADM-03 — Управление доступом
Как администратор, я хочу блокировать и восстанавливать доступ пользователей, чтобы контролировать использование системы.

Критерии приёмки:
- Заблокированный пользователь не может войти или выполнять защищённые операции, в том числе с ранее выданной сессией.
- После восстановления доступа пользователь может снова войти.
- Блокировка не удаляет историю приёмов и медицинские записи.

### ADM-04 — Контроль записей на приём
Как администратор, я хочу просматривать записи с фильтрацией по врачу, дате и статусу, чтобы координировать работу клиники.

Критерии приёмки:
- В списке видны пациент, врач, время и статус записи.
- Фильтры можно применять совместно и сбрасывать.
- При отсутствии записей отображается понятное сообщение.

### ADM-05 — Вывод врача из расписания
Как администратор, я хочу отключать возможность новых записей к врачу, который больше не принимает, чтобы пациенты выбирали только доступных специалистов.

Критерии приёмки:
- Неактивного врача нельзя выбрать для новой записи.
- Существующие записи и история сохраняются.
- Система показывает будущие записи к этому врачу, требующие переноса или отмены.

## Пациент

### PAT-01 — Регистрация и вход
Как пациент, я хочу создать учётную запись и войти в личный кабинет, чтобы самостоятельно управлять своими приёмами.

Критерии приёмки:
- Система проверяет обязательные поля и уникальность идентификатора входа.
- При успешном входе открывается личный кабинет пациента.
- Пациент не получает доступ к чужим записям через интерфейс или прямой запрос к API.

### PAT-02 — Поиск врача и свободного времени
Как пациент, я хочу искать врача по имени и специализации и просматривать свободные интервалы на выбранную дату, чтобы подобрать удобный приём.

Критерии приёмки:
- Поиск возвращает только подходящих активных врачей.
- Занятые интервалы и время в прошлом недоступны для выбора.
- Если свободного времени нет, система предлагает выбрать другую дату или врача.

### PAT-03 — Запись на приём
Как пациент, я хочу записаться к выбранному врачу на свободное время, чтобы получить консультацию.

Критерии приёмки:
- Перед подтверждением видны врач, дата и время приёма.
- Сервер повторно проверяет доступность интервала при сохранении; два пациента не могут занять один интервал врача.
- Успешная запись появляется в личном кабинете; при конфликте предлагается выбрать другое время.

### PAT-04 — Просмотр своих приёмов
Как пациент, я хочу видеть предстоящие и прошлые приёмы, чтобы отслеживать своё расписание и историю посещений.

Критерии приёмки:
- Для каждой записи показаны врач, дата, время и статус.
- Предстоящие приёмы отделены от завершённых и отменённых.
- Отображаются только записи текущего пациента.

### PAT-05 — Перенос и отмена приёма
Как пациент, я хочу переносить или отменять будущие записи, чтобы менять планы без обращения в клинику.

Критерии приёмки:
- Для переноса можно выбрать только свободное будущее время.
- Если перенос не удался, исходная запись сохраняется без изменений.
- Перед отменой требуется подтверждение; после отмены статус обновляется, а интервал освобождается.
- Завершённую или уже отменённую запись нельзя повторно отменить или перенести.

### PAT-06 — Просмотр рецептов
Как пациент, я хочу просматривать рецепты, выписанные после приёмов, чтобы следовать назначениям врача.

Критерии приёмки:
- Рецепт содержит врача, дату назначения, препарат, дозировку и инструкции по применению.
- Пациент может читать только собственные рецепты и не может изменять назначения.
- Если рецептов нет, отображается соответствующее сообщение.

## Врач

### DOC-01 — Вход в рабочий кабинет
Как врач, я хочу входить в персональную панель, чтобы работать со своим расписанием и пациентами.

Критерии приёмки:
- После успешной проверки учётных данных открывается панель врача.
- Сервер проверяет роль и активность учётной записи при защищённых операциях.
- Выход из системы прекращает доступ в рамках текущей сессии.

### DOC-02 — Управление доступностью
Как врач, я хочу задавать рабочие интервалы и периоды отсутствия, чтобы пациенты записывались только на время, когда я принимаю.

Критерии приёмки:
- Интервал окончания должен быть позже начала, а рабочие интервалы не должны пересекаться.
- Изменения доступности отражаются в выборе времени для пациентов.
- Если изменение затрагивает существующие записи, система сообщает о конфликте и не отменяет их автоматически.

### DOC-03 — Просмотр расписания
Как врач, я хочу видеть свои записи на выбранную дату, чтобы подготовиться к приёмам.

Критерии приёмки:
- Записи отсортированы по времени и содержат пациента и статус.
- Врач может выбрать другую дату.
- Изменение параметров API не позволяет получить чужое расписание без соответствующих прав.

### DOC-04 — Просмотр медицинской истории пациента
Как врач, я хочу просматривать доступные медицинские записи пациента, записанного ко мне, чтобы учитывать прошлые обращения и назначения.

Критерии приёмки:
- Медицинская история открывается из записи на приём.
- Сервер проверяет право врача на доступ к выбранному пациенту.
- История показывает даты обращений и связанные назначения; отсутствие истории явно обозначено.

### DOC-05 — Завершение приёма
Как врач, я хочу сохранять результаты консультации и отмечать приём завершённым, чтобы вести историю лечения.

Критерии приёмки:
- Врач может изменять только разрешённые ему записи на приём.
- Результаты консультации сохраняются и доступны при последующем просмотре.
- При ошибке сохранения система сообщает об этом и не показывает приём как успешно завершённый.
- Отменённый приём нельзя отметить завершённым.

### DOC-06 — Выписка рецепта
Как врач, я хочу выписывать рецепт по результатам приёма, чтобы пациент получил понятные назначения.

Критерии приёмки:
- Рецепт связан с пациентом, врачом и конкретным приёмом.
- Перед сохранением проверяются препарат, дозировка и инструкции по применению.
- Успешно сохранённый рецепт доступен врачу и соответствующему пациенту.
- При ошибке сохранения отображается ошибка, а интерфейс не сообщает об успешной выписке.
