## Раздел 1: Обзор архитектуры

Целевая архитектура Smart Clinic Management System разделяет интерфейс и серверную логику: React-приложение отображает панели администратора и врача, а также страницы записей на приём, кабинета пациента и медицинских записей. Вместо показанных на исходной схеме Thymeleaf-контроллеров панели обращаются к REST-контроллерам Spring Boot по HTTP и обмениваются данными в формате JSON. React отвечает за отображение и взаимодействие с пользователем, а сервер — за проверку прав доступа, валидацию и выполнение бизнес-операций. Сейчас в `frontend/` создан стартовый React-проект; подключение к API и реализация серверных заготовок остаются следующими этапами. Существующие Thymeleaf-файлы относятся к исходному шаблону.

REST-контроллеры передают запросы общему сервисному слою, который выполняет бизнес-логику и обращается к соответствующим репозиториям. Данные пациентов, врачей, записей на приём и администраторов хранятся в PostgreSQL и представлены JPA-сущностями `Patient`, `Doctor`, `Appointment` и `Admin`. Рецепты хранятся отдельно в MongoDB в виде документов `Prescription`. Доступ к хранилищам выполняется через Spring Data JPA и Spring Data MongoDB; браузер взаимодействует только с серверным API.

## Раздел 2: Нумерованный поток данных и управления

1. Пользователь открывает React-панель администратора или врача либо страницу записей на приём, кабинета пациента или медицинской карты и выполняет действие в интерфейсе.
2. React отправляет HTTP-запрос соответствующему REST-контроллеру Spring Boot. В адаптированной схеме этот путь используется и для панелей управления: серверу не требуется формировать Thymeleaf-страницы.
3. Контроллер принимает параметры или JSON, инициирует проверку данных и прав доступа и передаёт операцию сервисному слою. Сервис выполняет бизнес-правила приложения.
4. Сервис выбирает репозиторий по типу данных: JPA-репозиторий для пациентов, врачей, записей и администраторов либо MongoDB-репозиторий для рецептов.
5. Репозиторий выполняет чтение или изменение данных в соответствующем хранилище — PostgreSQL или MongoDB.
6. Слой доступа к данным сопоставляет строки PostgreSQL с JPA-сущностями, а документы MongoDB — с моделью `Prescription`. При сохранении используется обратное преобразование объектов в данные хранилища.
7. Объекты `Patient`, `Doctor`, `Appointment`, `Admin` или `Prescription` возвращаются через репозиторий в сервисный слой. Контроллер формирует JSON-ответ с необходимыми данными, предпочтительно через DTO без секретных полей, а React обновляет интерфейс или показывает ошибку операции.
